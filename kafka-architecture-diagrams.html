Key Architectural Highlights:

  • Unified Dual Templates: Dedicated strongly-typed template for domain events plus a generic Object template for tombstone deletion semantics.

1. Non-Blocking Retry Topics Pattern

@RetryableTopic + Exponential Backoff

Traditional blocking retries sleep the consumer thread, stalling processing for all subsequent healthy messages on the same partition (Head-of-Line Blocking). Spring Kafka's @RetryableTopic reroutes failed messages to separate retry topics with backoff delays, allowing subsequent messages to proceed immediately.

Advantages of Non-Blocking Retries:

  • Zero Head-of-Line Blocking: A poisoned or failing message never blocks partition offset progression for remaining messages.
  • Dynamic Exponential Backoff: Uses separate topics with graduated delays (delay = 1000ms, multiplier = 2.0).
  • Automated DLT Recovery: Captures terminal failures in @DltHandler for immediate alerting and diagnosis.

2. Manual Acknowledgment & Nack Backpressure

AckMode.MANUAL_IMMEDIATE

Provides fine-grained programmatic control over consumer offsets. When processing succeeds, acknowledgment.acknowledge() commits the offset immediately to Kafka. When transient downstream errors occur, acknowledgment.nack(Duration.ofMillis(1000)) pauses polling and initiates controlled redelivery without losing position.

Manual Acknowledgment Capabilities:

  • Deterministic Commit Timing: Guarantees that message offset is committed only after external operations (such as SQL write or remote RPC) succeed.
  • Graceful Backpressure via nack(): Gives downstream databases or services time to recover without crashing container threads.
  • Container Setting: Configured via factory.getContainerProperties().setAckMode(AckMode.MANUAL_IMMEDIATE).

4. Kafka Log Compaction & Tombstone Deletion

cleanup.policy = compact

Log compaction ensures that Kafka retains at least the last known value for each record key within the partition log. Sending a record with a non-null key and a null value creates a tombstone record, instructing Kafka's log cleaner to delete the key permanently.

Log Compaction Properties & Rules:

  • Configuration: cleanup.policy=compact, min.compaction.lag.ms=0, and segment.ms=10000.
  • Table-Stream Duality: Converts a changelog event stream into a materialized key-value table representation.
  • Tombstone Cleanup: A record with payload == null signals deletion. Once delete.retention.ms elapses, both the key and tombstone are removed from disk.

5. Exactly-Once Semantics & Transactional Publishing

2-Phase Commit (2PC) on Kafka

Atomic multi-message and multi-partition publishing using Kafka's transaction coordinator. Read-committed consumers will never observe partial or aborted batches.

Transactional Guarantees:

  • Atomic Multi-Partition Writes: All messages across diverse topics/partitions commit or abort as an atomic unit.
  • Idempotent Producer: Prevents duplicates caused by network retries via internal sequence numbers (enable.idempotence=true).
  • Zombie Fencing: Producer epochs prevent older zombie producer instances from writing to partitions after rebalances.

7. Cooperative Sticky Rebalancing

CooperativeStickyAssignor

Traditional Eager rebalancing stops the world across all consumers in the group during membership changes. The CooperativeStickyAssignor performs incremental assignment: only partitions being migrated are revoked, allowing unaffected consumers to continue consuming without interruption.

9. Tiered Storage (KIP-405) & MirrorMaker 2.0 Disaster Recovery

Infinite Event Retention & Multi-Cluster Replication

Tiered Storage offloads aged log segments to cloud object storage (S3 / GCS) while keeping hot segments on local NVMe SSDs. MirrorMaker 2.0 replicates topic topologies, partition offsets, and ACLs across geo-distributed primary and secondary clusters.
